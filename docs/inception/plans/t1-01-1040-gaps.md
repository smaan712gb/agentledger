# T1-01 plan: 1040 gaps to `preparation-validated`

Read-only study of the engine, 2026-10-09. Build plan for Forms 1116, 8615, 8880, 8962, 8606, 8889, 4797, 8582,
2210, the capital loss carryover worksheet and Form 1040-X. Status per slice is kept in backlog.md (T1-01).

## Precondition owned by the business

`coverage/coverage.yaml` has `owner: null`. By its own rule ("preparation-validated = independent fixtures pass and
the tax-content owner signed off; code checking its own output is not evidence") nothing moves to
`preparation-validated` until a named tax-content owner reviews each slice. Slices are built and proven against IRS
worked examples first; the coverage move is the owner's sign-off step.

## Engine facts the plan rests on

- `returns/individual.py` computes TY2026 lines in a fixed order (dependents → wages → interest/dividends →
  retirement → Sch C → SE → Sch D → Sch E/Sch 1 → SS → AGI → deductions → tax → AMT → credits → other taxes →
  payments → unsupported checks). Lines are whole dollars in `Sheets`, keyed by engine form keys. Every statutory
  figure is `ctx.param(rule_id, date(y, 12, 31))` from `rules/**/*.yaml` (effective-dated, cited; `MissingValue`
  when no value covers the date — a missing figure blocks, never guesses).
- Inputs are facts and documents only. Three fields violate that today and are retired by this ticket:
  `Adjustments.hsa_deduction` (8889), `Adjustments.ira_deduction` (8606 worksheet), `excess_aptc_repayment` /
  `net_premium_tax_credit` (8962); `retirement_savings_contributions` is never computed (8880).
- `documents.py` BOXES populate W-2, 1099-INT, 1099-DIV, 1099-R, SSA-1099, 1099-G (+ summed 1098/1098-E).
  `facts.py` REQUIRED / IMPLIED / CODED are enforced at every gate. Unknown input keys are refused at any depth, so
  every new input needs a model field. New document types: 1099-SA, 5498, 5498-SA, 1095-A, prior-year return.
- There is no prior-year return link for computation; prior-year amounts are hand-entered inputs. Invariant test:
  every model field whose name contains carryover / carryforward / prior_year / unallowed is in
  `store.CARRYOVER_INPUTS` and vice versa.
- Oracle: `returns/oracle.py` compares 13 tax-unit variables with PolicyEngine-US 2.33; `_unmodelled` names what
  the adapter cannot express. Golden: `golden/scenarios.yaml` (`calc: form_1040_line`), `agentledger golden`.
- `start_amendment` creates a `1040-X` return copying inputs, provenance and dispositions; the `f1040x` form key is
  only named, never computed; `approved_version` is stored but never read (the natural "as originally filed" pin).
- docs/irs (untracked) holds the e-file packet and ATS scenarios only; none of the eleven items' 2026 drafts or
  instructions. The owner should download them (and Pub 514, 590-A/B, 925, 969, 974 examples) before each slice.
