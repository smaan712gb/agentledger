## Re-audit of 9333fde (same day): four database-boundary and provisioning findings, fixed

F-04 was reopened for these and closed again once each had a failing test that now passes. Tests live in
`tests/test_reaudit_9333fde.py` and run in CI against PostgreSQL 17; findings 1, 2 and the provisioning path were also
verified against the Neon dev branch (`test_neon_database_per_firm_live`).

| # | Finding | Fix | Proof (test) |
|---|---|---|---|
| D1 (high) | Runtime connections logged in with the migration owner's credentials and used `SET ROLE`; `RESET ROLE` restored owner privileges, and the shared application role could read another firm's schema | Each store has its own runtime login role (`rt_<database>_<schema>`): no superuser, role creation, database creation, RLS bypass or inheritance, owns nothing, privileges only in its own schema or database (database tenancy also revokes CONNECT from PUBLIC). Runtime connections log in as that role, so there is no role to reset into. Owner credentials are used only to migrate and provision (`AGENTLEDGER_MIGRATION_URL`); runtime passwords derive from `AGENTLEDGER_DB_ROLE_KEY`, so none is stored | `test_runtime_connection_cannot_regain_owner_privileges`, `test_runtime_connection_cannot_read_another_firm` |
| D2 (high) | RLS covered return headers but not return versions, workflow history and other child records; a session scoped to client A read B's history and added a version to B's return | Child tables follow their parent's policy for reads and writes (return versions, workflow events, document links, finding resolutions, command receipts); rows without a client (unassigned inbox, firm settings) are visible to firm-wide sessions only. API requests now set the session scope per request: a client user's session sees only their business | `test_client_scope_covers_child_records_for_reads_and_writes`, `test_api_scopes_client_users_to_their_business` |
| D3 (medium) | Receipt matching cast money to `REAL`; $19.99 did not match $19.99 on PostgreSQL | Exact `Decimal` comparison on both backends | `test_receipt_links_to_expense_with_cents` (19.99, 1,234.56, 0.10, 98,765.43; a one-cent difference does not match) |
| D4 (medium) | A migration failure after Neon created the firm database left an orphan that blocked every retry | Provisioning is a durable, journaled operation (`creating → created → migrated → ready`) recorded before anything is created. The firm stays in status `provisioning` (unusable) until its store is ready | `test_migration_failure_after_creation_resumes_on_retry`, `test_timeout_after_creation_is_resumed_not_duplicated`, `test_existing_database_without_a_record_is_never_adopted`, `test_concurrent_retry_is_refused_while_another_holds_the_lease`, `test_abandon_removes_only_what_provisioning_created` |

Also found while fixing D1: on Neon the owner is not a superuser, so `DROP OWNED BY` a runtime role is refused; the
role is now dropped by revoking its remaining grants. Seven test roles left on the Neon dev branch by the failing
run were removed.

Residual, unchanged: firm staff sessions are firm-wide until engagement grants arrive (F-05), and the session scope is
a setting the runtime role itself can change, so it limits mistakes inside one firm rather than a compromised
process (cross-firm isolation is the role and database boundary above). Workflow history is scoped through return
ids; workflows of other kinds will carry their client explicitly.
