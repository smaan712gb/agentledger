**Second review round.** Four reviewers re-attacked the fixed code and demonstrated 35 more defects, all fixed, each
with a regression test (`tests/test_reaudit_952ee96_round2_*.py`). The ones that changed the design:

- Firm offboarding: a cancellation could land in the middle of a running deletion. A run now holds a lease; a
  cancellation during a run stops it at its next stage and is refused once the store's removal has begun (recorded
  before the store is touched, atomically with the cancellation check); the removal re-verifies the seal in the same
  locked step; every failure before removal unseals; the store's server and the object store's location are recorded
  when the firm is created and a job configured for another is refused (a firm created before that, with none on
  record, is refused until an operator records it: `record_blob_location`, never inferred); an abandonment the same
  outage stops before it can unseal the store records that (`firm_abandon_stuck`), and the firm's activation unseals
  the store first or keeps the firm out of use (before, the firm went live sealed and every hold was refused); a
  cancellation is recorded only against a run still holding the lease, and a new offboarding begins with no request
  left over from an earlier one; firm ids are matched exactly and reserved ids
  refused everywhere; a platform root inside a "tenants" directory is refused.
- Deletion: no lock is held across a call to storage any more (a PostgreSQL session that ends mid-call released its
  locks while the delete still landed). An in-flight marker with a deadline commits first; a hold placed meanwhile is
  told which objects it cannot keep; the lock set is re-checked once locked; a return's version and the documents it
  relies on are saved in one locked transaction.
- Facts: a document that leaves is noticed even when it was the only one of its kind (and for summed amounts);
  implied amounts must be positive; the owner a W-2 names is a sourced fact; amendments keep the filed return's
  dispositions; fields intake grounding drops block review as unconfirmed instead of vanishing; unknown inputs are
  refused at every depth.
- Retention: annual employment forms count only when filed; class groups are pinned; foreign tax is detected under
  any box spelling and from the returns that relied on a document; carryovers are an explicit list; pass-through
  status follows the returns filed; and two dead ends were removed: a CPA can release a basis record once the
  property is disposed of (it is then kept as a record of the disposition year), and an AgentLedger return that will
  not be filed through it can be voided.

Residual, documented rather than fixed:

- Circumstances no rule sees (fraud, an agreement extending the assessment period, an unfiled foreign information
  return, an undisclosed listed transaction, a pending claim or suit) are covered by the CPA's attestation on each
  retention run and by legal holds.
- A delete call in flight on a PostgreSQL connection that drops while a hold is being placed can land after the hold;
  the next run reports it ("held, bytes already gone"). Bucket-level object locks on held prefixes (F-13) close it.
- Firm deletion is an operations job with owner database credentials and has no API route yet; when it gets one it
  needs platform-administrator step-up. The firm's export bundle (A1-10) must be delivered first.
- Documents are unique per firm by hash: an identical upload into another client's workspace names the other
  client's document on SQLite and is refused with an error on PostgreSQL. Documents should be unique per client
  (F-05 follow-up).
- Fiscal-year due dates and the owners of a pass-through entity are recorded by a CPA (`due_on`, `owners_filed`);
  there is no fiscal-year or entity-owner model yet.
